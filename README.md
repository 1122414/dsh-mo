# dsh-mo · 自己给自己涨薪

一个关于自己给自己涨薪的 DSH 插件。**Agent 连续自主执行 5 秒后，开始累计摸鱼时间，实时显示带薪时间价值与折算有效时薪。**

当前版本：`0.1.0-alpha.1`。计时引擎、悬浮界面、设置、7 日记录和独立演示已实现。**尚未完成真实 DSH Web / Desktop 的安装与运行验收，不是已验证兼容所有 DSH 版本的正式版。**

## 已实现

- 连续运行的前 5 秒不计入；65 秒任务计为 60 秒。连续工具调用不重复扣 5 秒。
- 读取 DSH 的统一 UI 会话状态，等待提问/授权时停止；恢复后重新走 5 秒准备期。
- 多会话时间取并集，两个 Agent 同跑一分钟最多记一分钟。
- 月薪、月工作日、每周工作日、上下班与午休设置。`月工作日=0` 按当月配置的星期自动统计。
- 今日折合工资、有效时薪、涨幅、带薪时长、全天计时时长；最近 7 日汇总。
- Shadow DOM 悬浮卡片、拖动、折叠、系统深浅主题、手动暂停。
- 本地保存最近 90 天的已确认区间，JSON 导出，确认后重置；异常数据不静默覆盖。
- Web Locks 单写者，多标签页避免重复记账。其他标签页只读。
- 无运行时依赖，无模型调用，无自建后台，不读取消息正文、工具参数、代码或工资之外的账号资料。

## 先看独立演示

```sh
git clone git@github.com:1122414/dsh-mo.git
cd dsh-mo
git checkout feat/moyu-meter-mvp
npm run preview
```

打开终端打印的 `http://127.0.0.1:4173/`。仓库已包含构建产物，单独运行演示只需 Node.js 22+，不需要 API Key。

先在右下角保存薪资设置，再用页面按钮模拟 A 开工、等待授权、B 并行、断开及重连。**这些按钮仅是 DSH 状态夹具，不会控制真实 Agent。** 演示数据与真实 DSH 在不同端口下隔离。

## 实验性安装到 DSH Web

在支持下述接口的 DSH 上，用你要测试的 Web profile 安装；建议先使用单独的测试 Harness home，避免影响日常配置。

```sh
dsh plugin --profile web add github:1122414/dsh-mo#feat/moyu-meter-mvp
```

安装后重启该 Web profile 并刷新页面。首次保存薪资设置后才开始计量。服务不可用、接口不兼容或连接断开时停止新增计时，不会猜测字段或抓取 DOM。

当前接入要求：`ctx.uiSession.sessionStatus`、`ctx.connection.generation`、浏览器 Web Locks。详见 [兼容性与验收](docs/COMPATIBILITY.md)。**普通 npm CLI 不应直接修改由桌面应用管理的 desktop profile；Desktop 暂列待验收。**

卸载：

```sh
dsh plugin --profile web remove dsh-mo
```

本地工资与记录不会因卸载自动删除；卸载前可在插件「记录」页导出或重置。

## 算法口径

设月薪 8,000 元、20 个工作日、每天 8 小时：基础时薪为 50 元。当日记到 2 小时带薪摸鱼时，时间价值为 100 元，全天折算有效时薪为 `400 / (8 - 2) = 66.67` 元，涨幅 `33.33%`。

```text
基础时薪 = 月薪 / 当月工作日 / 每日计划工时
带薪时间价值 = 基础时薪 × 工作时间内的摸鱼小时数
全天折算有效时薪 = 日薪 / (每日计划工时 - 当日带薪摸鱼小时数)
```

这是假设日薪不变、将已累计的摸鱼时间从全天计划工时中扣除的**娱乐化时间分摊指标**，不是实时到手工资、法定工资计算或真实生产效率测量。达到全天工时上限时显示「已达当日上限」，不显示无穷大或继续虚增。

## 计量与数据边界

- 只记录页面运行、连接可靠时观察到的时间。切到后台可继续计量，但浏览器节流/休眠造成采样间隔 **超过 15 秒** 时，空白段不补算，重新开始 5 秒门槛。
- 刷新和重启只恢复已保存区间，不推测关闭期间发生了什么。常规每 5 秒保存及状态变化时保存，突发崩溃可能丢失最后约 5 秒未落盘记录。
- 计时器用于采样与刷新；计算使用时间戳，不按 tick 数累加。系统时钟倒退时保守停止，直到追上最后时间。
- 工资仅按配置的上班区间计入，午休和周末不计带薪收益；全天观察时间单列展示。
- 数据保存在当前浏览器 origin 的 `localStorage['dsh-mo:v1']`。换端口/浏览器/设备不共享，清缓存会丢失。没有云同步或加密。
- 每个 origin 只有一个标签页持有记录锁。后打开的页面只读；缺少 Web Locks 时也只读，不采用可能双写的降级方案。
- 修改薪资/班次会用新配置**重新计算历史金额**；首版不是冻结历史费率的财务账本。
- 首版只支持人民币、浏览器本地时区、当日班次与固定星期工作制；**不含法定节假日/调休日表、跨夜班、单次记录编辑、JSON 导入和每任务归因**。自动工作日也只按星期计算。
- 「Agent 在工作」只是用户选定的摸鱼代理指标；不会监控你是否正在别的软件工作。

## 开发与检查

```sh
npm install
npm run check
npm run preview
```

开发依赖精确固定为 TypeScript 5.8.3；没有运行时依赖。`npm run build` 用 TypeScript 编译后生成本地模块表，不使用 `eval`、动态远程导入或 DSH 私有网络路由。`lib/` 提交在仓库中，因此 GitHub 安装不需要执行构建脚本。修改 `src/` 后必须重新生成 `lib/`。

本次本地检查：Node.js 22.16.0、TypeScript 5.8.3，`npm run check` 的 **43 项 Node 测试通过**。另有 **8 项离线 Chromium DOM 夹具检查通过**（Storage/Web Locks 为测试替身，不能证明真实多标签页互斥）。真实 localhost 浏览器导航被执行环境管理策略阻止，完整浏览器与 DSH 集成仍待验证。

可选浏览器检查（需自行准备 Python Playwright 和 Chromium）：

```sh
python tests/browser-offline.py  # 离线 DOM 夹具，显式模拟 Storage / Locks
python tests/browser-smoke.py   # 本机 HTTP 夹具，含真实同源多标签页；本次尚未跑通
```

`CHROMIUM_PATH` 可指定浏览器路径。浏览器测试不是默认 Node 检查的一部分。

目录、接入来源和下一步请见 [开发说明](docs/DEVELOPMENT.md) 与 [兼容性与验收](docs/COMPATIBILITY.md)。
